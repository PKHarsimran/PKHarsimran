# Signal Heist, snapshot relics and rewind

The public profile lab adds an opt-in README puzzle using the same three repository snapshots and public contribution calendar. The card supplies all three facts and their digit rules. A hash of the recipe version, UTC snapshot date, selected project fields and calendar days determines the route, decoy order, creature name and symmetric pixel pattern. The manifest records the clues, answer and full fingerprint so the result can be reproduced. Code hatches are native Markdown details; they do not submit reader input or record guesses.

Clue cards and relics have fingerprinted filenames so cached README editions keep matching clues and answers. The last 14 editions remain in the generator-owned `profile/arcade/` directory; only matching obsolete generated SVG names are pruned.

The rewind compares release tags, observed CI states, star counts and latest commit timestamps with the previous saved public radar snapshot. An unchanged or first snapshot gets an explicit quiet or initial state. It does not infer deployments, uptime, human effort or private repository events.

Run `python3 scripts/generate_profile_lab.py --readme README.md` to refresh the artifacts and the single bounded `arcade-lab` slot. Omitting `--readme` generates artifacts without editing the README. All sources and the slot are validated before output files are written. The daily workflow publishes the matching card, relic, manifest and README together.
